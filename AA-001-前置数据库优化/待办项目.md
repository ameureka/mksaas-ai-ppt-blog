## 三、待办项目

### 🔴 高优先级 (影响数据完整性)

#### TODO-1: slide.ppt_id 添加外键约束
- **问题**: slide 表的 ppt_id 字段无外键约束，PPT 删除后幻灯片成为孤儿数据
- **影响**: -4 分
- **解决方案**:
```typescript
// src/db/schema.ts
pptId: text("ppt_id").references(() => ppt.id, { onDelete: 'cascade' })
```
- **迁移 SQL**:
```sql
ALTER TABLE slide 
ADD CONSTRAINT slide_ppt_id_fkey 
FOREIGN KEY (ppt_id) REFERENCES ppt(id) ON DELETE CASCADE;
```
- **风险**: 低，slide 与 ppt 是强关联关系
- **状态**: ⏳ 待处理

---

### 🟡 中优先级 (代码质量)

#### TODO-2: 清理重复索引 session_token_idx
- **问题**: session.token 已有 UNIQUE 约束，额外的索引冗余
- **影响**: -1 分
- **解决方案**: 移除 session_token_idx 或保留用于查询优化
- **建议**: 保留，UNIQUE 约束和索引用途不同
- **状态**: ⏳ 评估中

#### TODO-3: 清理重复索引 idx_import_batch_status
- **问题**: import_batch 表存在重复的 status 索引
- **影响**: -1 分
- **解决方案**:
```sql
DROP INDEX IF EXISTS idx_import_batch_status;
-- 保留 import_batch_status_idx
```
- **状态**: ⏳ 待处理

#### TODO-4: category.parent_id 外键策略优化
- **问题**: 当前为 NO ACTION，父分类删除时子分类处理不明确
- **影响**: -1 分
- **解决方案**:
```typescript
parentId: text("parent_id").references(() => category.id, { onDelete: 'set null' })
```
- **效果**: 父分类删除时，子分类变为顶级分类
- **状态**: ⏳ 待处理
