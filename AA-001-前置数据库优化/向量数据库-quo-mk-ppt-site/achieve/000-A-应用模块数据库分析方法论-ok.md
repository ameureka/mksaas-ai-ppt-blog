## 各步骤详细说明

### Step 1: 定位常量/配置定义

**目标**: 找到功能模块的核心配置和映射关系

**查找位置**:
- `src/lib/constants/` - 常量定义
- `src/config/` - 配置文件
- 组件内部的 hardcoded 值

**关注点**:
```typescript
// 典型的 label/value 映射
export const CATEGORIES = [
  { label: '显示名称', value: 'db_value' },
] as const;

// 类型定义
export type CategoryValue = typeof CATEGORIES[number]['value'];
```

**输出**: 映射表、枚举值列表、配置项清单

---

### Step 2: 定位数据库 Schema

**目标**: 理解数据存储结构

**查找位置**:
- `src/db/schema.ts` - Drizzle 表定义
- `drizzle/migrations/` - 迁移文件
- 数据库直接查询 `\d table_name`

**关注点**:
```typescript
export const tableName = pgTable("table_name", {
  id: text("id").primaryKey(),
  field: text("field"),           // 字段类型
  status: text("status"),         // 状态字段
  deletedAt: timestamp("deleted_at"), // 软删除
});

// 索引定义
export const tableNameIdx = index("idx_name").on(tableName.field);
```

**输出**: 字段清单、类型、约束、索引

---

### Step 3: 追踪路由层

**目标**: 理解 URL 如何映射到数据查询

**查找位置**:
- `src/app/[locale]/(marketing)/` - 营销页面
- `src/app/[locale]/(protected)/` - 受保护页面
- `src/app/api/` - API 路由

**关注点**:
```typescript
// 动态路由参数
// 文件: /ppt/category/[name]/page.tsx
const params = useParams();
const slug = params.name; // URL 参数

// 查询参数
const searchParams = useSearchParams();
const page = searchParams.get('page');
```

**输出**: URL 结构、参数映射、页面组件位置

---

### Step 4: 追踪 API 层

**目标**: 理解请求处理流程

**查找位置**:
- `src/app/api/*/route.ts` - API 路由
- `src/actions/` - Server Actions

**关注点**:
```typescript
// API 路由
export async function GET(request: Request) {
  const { searchParams } = new URL(request.url);
  const param = searchParams.get('param');
  
  const result = await getData({ param });
  return Response.json(result);
}

// Server Action
'use server'
export async function getData(params: Params) {
  // 业务逻辑
}
```

**输出**: 请求参数、响应格式、调用链

---

### Step 5: 追踪数据访问层

**目标**: 理解 ORM 查询构建

**查找位置**:
- `src/actions/` - 数据操作
- `src/db/` - 数据库工具

**关注点**:
```typescript
// Drizzle 查询构建
const conditions = [
  isNull(table.deletedAt),        // 软删除过滤
  eq(table.field, value),         // 精确匹配
  like(table.title, `%${search}%`), // 模糊搜索
];

const rows = await db
  .select()
  .from(table)
  .where(and(...conditions))
  .orderBy(desc(table.createdAt))
  .limit(pageSize)
  .offset((page - 1) * pageSize);
```

**输出**: 查询条件、排序规则、分页逻辑

---

### Step 6: 生成 SQL 分析

**目标**: 理解最终执行的数据库操作

**方法**:
1. 从 ORM 代码推导 SQL
2. 开启 Drizzle 日志查看实际 SQL
3. 使用 `EXPLAIN ANALYZE` 分析执行计划

**关注点**:
```sql
-- 典型查询
SELECT * FROM table
WHERE deleted_at IS NULL
  AND category = 'value'
ORDER BY created_at DESC
LIMIT 12 OFFSET 0;

-- 索引使用
EXPLAIN ANALYZE SELECT ...;
```

**输出**: SQL 语句、索引使用情况、性能指标

---

### Step 7: 绘制架构图

**目标**: 可视化整体数据流

**图表类型**:
1. **数据流图**: 从用户操作到数据库的完整链路
2. **组件关系图**: 前端组件、API、数据层的依赖
3. **表关系图**: 数据库表之间的关联

**模板**:
```
用户操作 → 前端组件 → API 调用 → 业务逻辑 → ORM 查询 → 数据库 → 返回数据 → 渲染
```

---

### Step 8: 分析优缺点 & 改进建议

**评估维度**:

| 维度 | 检查项 |
|------|--------|
| 数据完整性 | 约束、外键、枚举、NOT NULL |
| 性能 | 索引覆盖、查询效率、N+1 问题 |
| 可维护性 | 代码组织、类型安全、重复代码 |
| 扩展性 | 新增字段/分类的难度 |
| 安全性 | SQL 注入、权限校验、数据泄露 |

**改进建议模板**:
```
### 数据库层面
- [ ] 添加约束/索引
- [ ] 优化查询

### 应用层面
- [ ] 集中配置管理
- [ ] 类型安全校验
- [ ] 缓存策略

### 性能优化
- [ ] 覆盖索引
- [ ] 分页优化
- [ ] 缓存层
```

## 快速检查清单

分析任意模块时，依次回答以下问题：

- [ ] 配置定义在哪里？有哪些可选值？
- [ ] 数据存在哪张表？字段类型是什么？
- [ ] URL 如何映射到查询参数？
- [ ] API 如何处理请求？
- [ ] ORM 如何构建查询？WHERE/ORDER/LIMIT？
- [ ] 使用了哪些索引？有无性能问题？
- [ ] 数据流是否清晰？有无冗余？
- [ ] 有哪些可以改进的地方？
