## PPTHub 生产数据库全面分析报告
#20251209
### 一、数据库架构概览

当前数据库基于 PostgreSQL + pgvector 扩展，使用 Drizzle ORM 管理，支持向量化搜索。

#### 核心技术栈
- **数据库**: PostgreSQL (Supabase/Neon/本地)
- **ORM**: Drizzle ORM
- **向量扩展**: pgvector (1024维向量)
- **向量模型**: BAAI/bge-m3 (多语言支持)
- **API 提供商**: 硅基流动 / OpenRouter

### 二、数据表结构详解

#### 1. 用户认证体系 (Better Auth)

user 表 - 用户主表
typescript
- id (PK): 用户唯一标识
- email (UNIQUE): 邮箱
- name, image: 基本信息
- createdAt, updatedAt: 创建/更新时间戳（Better Auth 写入）
- emailVerified: 邮箱验证状态
- role: 角色 (admin/user)
- banned, banReason, banExpires: 封禁机制
- customerId: Stripe 客户 ID
- deletedAt: 软删除标记 (R6优化)
- 索引: customer_id, role

代码对应:
- schema 定义: `src/db/schema.ts` → `export const user`
- 主要链路: Better Auth drizzleAdapter 在 `src/lib/auth.ts` 自动读写；业务侧更新/查询 customerId 与用户信息见 `src/payment/provider/stripe.ts`、`src/actions/get-users.ts`、`src/credits/distribute.ts`


session 表 - 会话管理
typescript
- id (PK): 会话主键
- token (UNIQUE): 会话令牌
- userId (FK → user): 关联用户
- expiresAt: 过期时间
- ipAddress, userAgent: 设备信息
- impersonatedBy: 管理员模拟登录
- createdAt, updatedAt: 会话创建/更新时间戳

代码对应:
- schema 定义: `src/db/schema.ts` → `export const session`
- 主要链路: 由 Better Auth 在 `src/lib/auth.ts` 内部自动读写，业务代码不直接访问


account 表 - 第三方账号绑定
typescript
- id (PK): 绑定记录主键
- providerId: OAuth 提供商 (github/google)
- accountId: 第三方账号 ID

- accessToken, refreshToken: OAuth 令牌
- idToken, scope: OAuth/SSO 附加信息（可空）
- accessTokenExpiresAt, refreshTokenExpiresAt: 令牌过期时间（可空）
- createdAt, updatedAt: 创建/更新时间戳
- 索引: user_id, account_id, provider_id

代码对应:
- schema 定义: `src/db/schema.ts` → `export const account`
- 主要链路: Better Auth 社交登录/账号绑定流程在 `src/lib/auth.ts` 自动读写


verification 表 - 邮箱/验证码校验（Better Auth）

- expiresAt: 过期时间
- createdAt, updatedAt: 创建/更新时间戳

- 主要链路: Better Auth 邮箱验证/重置密码等流程在 `src/lib/auth.ts` 自动读写

#### 2. PPT 核心业务表

ppt 表 - PPT 模板主表 ⭐
typescript
核心字段:
- id (PK): ppt_{uuid}
- tenantId: 多租户预留字段（当前可空）
- title (NOT NULL): 标题 (R7强制约束)
- description: 描述 (R10新增，用于SEO)
- fileUrl (NOT NULL): 文件地址 (R7强制约束)
- coverImageUrl, thumbnailUrl: 封面/缩略图
- author: 作者/上传者（当前可空）

分类与标签:
- category: 分类 (business/education/marketing等)
- tags: 标签数组 (text[])
- language: 语言 (en/zh)

统计数据:
- downloadCount: 下载次数
- viewCount: 浏览次数
- slidesCount: 幻灯片数量

向量化字段 (核心):
- embedding: vector(1024) - pgvector 向量（已建 HNSW 索引 `ppt_embedding_idx`）
- embeddingModel: 'BAAI/bge-m3'
- embeddingId: 向量化任务 ID (预留)
- embeddingStatus: pending/success/failed - 向量生成状态（2025-12-12 热修复新增）
- embeddingError: 最近一次失败原因（可空）
- embeddingUpdatedAt: 最近一次 embedding 尝试时间（可空，用于补漏/监控）

元数据 (R10新增):
- fileSize: 文件大小 (字节)
- fileFormat: 文件格式 (默认 pptx)

状态管理:
- status: draft/published/archived
- visibility: public/private
- reviewStatus: 审核状态
- deletedAt: 软删除 (R6)
- createdAt, updatedAt: 创建/更新时间戳

索引优化:
- 单列/复合索引: category, status, language, created_at, download_count, view_count；复合 (status, created_at)
- 向量索引: HNSW (`ppt_embedding_idx`, vector_cosine_ops)
- 备注: `ppt_embedding_idx` 由迁移脚本创建（如 `scripts/db-migration/add-embedding.sql` / `scripts/setup-pgvector.ts`），schema 仅声明字段

代码对应:
- schema 定义: `src/db/schema.ts` → `export const ppt`
- 主要链路: CRUD 在 `src/actions/ppt/ppt.ts`；向量/混合搜索在 `src/actions/ppt/search.ts`；首页与列表接口 `/api/ppts` 在 `src/app/api/ppts/route.ts`；下载接口 `/api/ppts/[id]/download` 在 `src/app/api/ppts/[id]/download/route.ts`

### 三、向量化搜索系统深度分析

#### 1. 向量化架构

用户搜索 → 生成查询向量 → pgvector 余弦相似度搜索 → 返回结果
                ↓
         BAAI/bge-m3 模型
         (1024维，多语言)


#### 2. 向量生成流程

输入文本构建 (generateEmbeddingInput)
typescript
输入 = title + description + tags.join(' ')
示例: "商业计划书 适用于创业融资的专业模板 商业 融资 创业"


API 调用 (generateEmbedding)
- 优先使用: 硅基流动 API (SILICONFLOW_API_KEY)
- 降级使用: OpenRouter API (OPENROUTER_API_KEY)
- 模型: BAAI/bge-m3 (免费，多语言，1024维)
- 返回: number[] (1024维向量)

存储方式
sql
UPDATE ppt
SET embedding = '[0.123, -0.456, ...]'::vector(1024),
    embedding_model = 'BAAI/bge-m3'
WHERE id = 'ppt_xxx'


#### 3. 搜索策略 (混合搜索)

vectorSearch - 向量搜索
sql
SELECT *,
  1 - (embedding <=> query_vector) as similarity
FROM ppt
WHERE deleted_at IS NULL AND status = 'published' AND embedding IS NOT NULL
ORDER BY embedding <=> query_vector
LIMIT 20

- 使用 <=> 余弦距离运算符
- 相似度 = 1 - 距离 (越接近1越相似)

sqlSearch - SQL 降级搜索
sql
WHERE deleted_at IS NULL AND status = 'published' AND (
  title ILIKE '%keyword%' OR
  description ILIKE '%keyword%' OR
  author ILIKE '%keyword%' OR
  array_to_string(tags, ',') ILIKE '%keyword%'
)
ORDER BY download_count DESC


hybridSearch - 混合策略
1. 尝试向量搜索
2. 结果 >= 5 条 → 返回向量结果
3. 结果 < 5 条 → SQL 补充
4. 向量失败 → 完全降级到 SQL


#### 4. 向量生成时机

- **创建 PPT**: createPPT → 异步调用 generatePPTEmbeddingAsync
- **更新 PPT**: updatePPT → 如果 title/tags 变更，重新生成
- **非阻塞**: 使用 async 函数，不阻塞主流程响应

// 2. 积分一致性检查
async function validateCredits(userId: string) {
  const [credit] = await db.select()
    .from(userCredit)
    .where(eq(userCredit.userId, userId));

  const transactions = await db.select()
    .from(creditTransaction)
    .where(eq(creditTransaction.userId, userId));

  const calculated = transactions.reduce((sum, t) => sum + t.amount, 0);

  if (calculated !== credit.currentCredits) {
    console.error('Credit mismatch:', { userId, calculated, actual: credit.currentCredits });
  }
}
