## PPTHub 向量数据库概览汇总
#20251212

> 目标：基于当前代码与数据库 schema，梳理向量字段、生成与检索链路、和首页/SEO/页面加载的交互关系，并评估合理性给出改进建议。

---

### 一、当前向量数据库实现概览

当前向量检索采用 **PostgreSQL + pgvector** 单库方案：
- **向量存储位置**：`ppt` 表内置 `embedding` 字段（`vector(1024)`），无独立 embeddings 表。  
  对应 schema：`src/db/schema.ts` → `export const ppt.embedding`
- **向量模型**：`BAAI/bge-m3`（多语言、1024 维），写入 `ppt.embedding_model`
- **相似度度量**：余弦相似度（`vector_cosine_ops` + `<=>` 距离）
- **索引**：HNSW 索引 `ppt_embedding_idx`  
  由脚本/迁移创建：`scripts/db-migration/add-embedding.sql`、`scripts/setup-pgvector.ts`

整体策略：**向量优先 + SQL 降级/补充**，主要用于首页无过滤搜索。

---

### 二、向量相关字段（与实际 schema 对应）

向量与检索直接相关字段位于 `ppt` 表：

- `embedding`：`vector(1024)`，PPT 语义向量  
  schema：`src/db/schema.ts` → `ppt.embedding`
- `embeddingModel`：当前写死为 `'BAAI/bge-m3'`  
  schema：`ppt.embeddingModel`
- `embeddingId`：预留的向量任务 ID（目前未使用）  
  schema：`ppt.embeddingId`
- `embeddingStatus`：embedding 生成状态（pending/success/failed）  
  schema：`ppt.embeddingStatus`
- `embeddingError`：最近一次失败原因（可空）  
  schema：`ppt.embeddingError`
- `embeddingUpdatedAt`：最近一次 embedding 尝试时间（可空，用于补漏/监控）  
  schema：`ppt.embeddingUpdatedAt`

向量生成输入依赖字段：
- `title`（NOT NULL）
- `description`（可空）
- `tags`（`text[]`）

检索过滤相关字段：
- `status`（published/draft/archived）
- `deletedAt`（软删除）
- 其他排序字段：`downloadCount`、`viewCount`、`createdAt`

### 三、向量生成原理与实现

#### 1. 输入构建
向量化文本由标题、描述、标签拼接：

代码：`src/lib/embedding.ts`
```ts
export function generateEmbeddingInput(ppt) {
  return [ppt.title, ppt.description || '', (ppt.tags || []).join(' ')]
    .filter(Boolean)
    .join(' ')
    .trim();
}
```

#### 2. 调用模型
`generateEmbedding(text)` 选择硅基流动 / OpenRouter embeddings API：
- 优先 `SILICONFLOW_API_KEY`，否则 `OPENROUTER_API_KEY`
- 模型：`BAAI/bge-m3`
- 输出：`number[]`（期望 1024 维）

代码：`src/lib/embedding.ts`

#### 3. 写入数据库
写入方式为 SQL UPDATE：
```sql
UPDATE ppt
SET embedding = '[...]'::vector,
    embedding_model = 'BAAI/bge-m3'
WHERE id = 'ppt_xxx';
```
对应实现：`src/lib/embedding-service.ts#generateAndPersist`（由 `src/actions/ppt/ppt.ts` 内部异步触发）

### 四、数据链路：向量写入（embedding 生成时机）

#### 1. 创建 PPT
链路：
1) 管理端/脚本调用 `createPPT`  
2) `ppt` 基本字段入库，同时初始化 `embedding_status='pending'`  
3) **异步**触发 `generatePPTEmbeddingAsync(id, { title, description, tags })`  
4) 生成 embedding 并 UPDATE 写入（成功/失败会落 `embedding_status/embedding_error/embedding_updated_at`）

代码入口：`src/actions/ppt/ppt.ts#createPPT`（插入后 fire-and-forget）

现状注意点：
- ✅ 2025‑12‑12 热修复：createPPT 已传入 description，embedding 输入包含 title+description+tags。
- ⚠️ 仍为 fire‑and‑forget：在 serverless 环境可能存在执行不完/被回收风险，需依赖 embedding_status + repair cron 补漏。

#### 2. 更新 PPT
链路：
1) `updatePPT` 更新字段  
2) 若 `title`/`description`/`tags` 变化，则将 `embedding_status` 置为 pending 并异步重算 embedding

代码入口：`src/actions/ppt/ppt.ts#updatePPT`

#### 3. 批量补全
仓库内存在脚本/说明（如 `pnpm generate-embeddings` 的想定）；同时已新增线上补漏端点 `/api/cron/repair-embeddings`（需配置 Cron 调用），用于批量重试 `embedding IS NULL` 或 `embedding_status != 'success'` 的记录。

### 五、数据链路：向量检索（首页搜索）

#### 1. API 入口
首页搜索请求：`GET /api/ppts?search=<keyword>`  
对应：`src/app/api/ppts/route.ts`

触发条件：仅当有 `search` 且 **无 category/status 过滤** 时使用混合检索。

#### 2. 向量检索 vectorSearch
链路：
1) 对 query 直接 `generateEmbedding(query)`（多语言模型）  
2) HNSW 向量近邻搜索：
```sql
SELECT id, title, description, author, category, tags,
       file_url, thumbnail_url, download_count, view_count, created_at,
       1 - (embedding <=> query_vector) as similarity
FROM ppt
WHERE deleted_at IS NULL
  AND status = 'published'
  AND embedding IS NOT NULL
ORDER BY embedding <=> query_vector
LIMIT 20;
```
代码：`src/actions/ppt/search.ts#vectorSearch`

#### 3. SQL 降级与补充 sqlSearch
当向量结果不足时，按 ILIKE 文本搜索补齐：
```sql
title/description/author/tags ILIKE %keyword%
ORDER BY download_count DESC
```
代码：`src/actions/ppt/search.ts#sqlSearch`

#### 4. hybridSearch 决策
逻辑（当前实现）：
1) 先向量搜索  
2) 结果先按 `similarity >= VECTOR_SIMILARITY_THRESHOLD`（默认 0.3）过滤  
3) 若过滤后结果 ≥ 5 → 直接返回 `searchType='vector'`  
4) 若 1~4 → SQL 补齐 → `searchType='hybrid'`  
5) 若 0 或向量失败 → SQL 降级 → `searchType='sql'`

代码：`src/actions/ppt/search.ts#hybridSearch`

#### 5. 搜索日志与热词
首页搜索会写 `search_log`（包括 searchType/duration/source 等）：
- 写入：`src/actions/ppt/search.ts#recordSearchLog`
- 热词/纠错/建议读取：`src/actions/hot-keywords.ts`、`src/actions/search/corrections.ts`、`src/app/api/search/suggestions/route.ts`

### 六、与页面加载/交互的关系

#### 1. 首页（PPT Hub 首页）
页面：`src/app/[locale]/(marketing)/ppt/page.tsx`（client）

加载/请求拆分：
- 首屏挂载后并行拉取：
  - 热词：`/api/hot-keywords`（基于 hot/pinned_keywords）
  - 分类统计：`/api/ppts/stats`
  - 精选/新品：`/api/ppts?...sortBy=downloads/created_at` → **走 SQL 列表**
- 用户在 hero 搜索框触发：
  - `/api/ppts?search=xxx` → **走 hybridSearch（向量优先）**

结论：向量检索只参与“无过滤搜索”，不影响首页其它模块的 SQL 列表与排序。

#### 2. 分类页/列表页
当带 `category`/`status`/排序参数时：
- `/api/ppts?...` → 走 `getPPTs`（纯 SQL + 中文变体 ILIKE）  
代码：`src/actions/ppt/ppt.ts#getPPTs`

因此向量语义搜索目前 **不会参与分类过滤后的搜索体验**。

#### 3. 详情页
详情页读取 `/api/ppts/[id]`（SQL 单条）；相关推荐同样走 SQL 按分类/下载量。
向量检索不参与详情页加载。

### 七、与 SEO（首页搜索引擎优化）的关系

#### 1. JSON‑LD SearchAction
首页内嵌 SearchAction 结构化数据：
`src/app/[locale]/(marketing)/ppt/page.tsx`（SearchAction urlTemplate 指向站内搜索）

价值：让搜索引擎识别“站内可搜索”能力，利于展示站点搜索框。

注意：urlTemplate 目前是示例 `https://ppt-ai.com/search?q=...`，需确保真实存在对应 SSR 搜索页或做重定向，否则结构化数据可能被判无效。

#### 2. 向量搜索对 SEO 的间接影响
- 提升搜索相关性 → 提高点击率/停留/下载 → 正向影响行为指标。
- 支持语义/同义词召回 → 增强“找得到”体验 → 降低跳出。

#### 3. 搜索页可索引性
当前首页搜索是 client fetch，不生成独立 URL/SSR 内容：
- **优点**：避免无限 query 组合被爬虫抓取、节省静态生成成本。
- **缺点**：长尾关键词没有独立落地页，不利于“搜索词 → 站内结果页”的 SEO 覆盖。

### 八、合理性评估

**合理部分**
- 单库 pgvector + HNSW 对 1e4~1e5 量级模板库足够，运维简单。
- BGE‑M3 多语言覆盖面好，适配中英混搜。
- 向量优先 + SQL 降级保证可用性（embedding 失败也能搜）。

**当前不足**
1) **向量生成可靠性不足**：fire‑and‑forget 在 serverless 场景可能丢任务；已增加 `embedding_status/embedding_error/embedding_updated_at` 记录 + repair cron 轻量补漏，但仍建议后续队列化。  
2) **创建时 embedding 输入不完整**：createPPT 没带 description（已在 2025‑12‑12 热修复中补齐）。  
3) **缺少相似度阈值**：向量结果可能“数量够但质量低”，却直接返回 vector（已在 2025‑12‑12 引入 `VECTOR_SIMILARITY_THRESHOLD` 门控）。  
4) **向量搜索未支持过滤条件**：用户在分类/语言筛选后搜索会退回 SQL，语义优势丢失。  
5) **查询 embedding 频繁远程调用**：高频搜索延迟/成本压力，无缓存。  
6) **索引/脚本一致性**：`setup-pgvector.ts`/`setup-search.sql` 中 search_log 定义与现 schema 已不一致，容易误用。

### 九、改进建议（按优先级）

**P1（应尽快做）**
1) **Embedding 生成可观测 + 可靠执行（已部分完成）**
   - ✅ 2025‑12‑12 热修复已新增 `embedding_status/embedding_error/embedding_updated_at`，并提供 `/api/cron/repair-embeddings` 批量补漏端点。
   - 后续仍建议引入后台任务/队列（如 Inngest/Cloudflare Queue/cron job），保证 create/update 后 embedding 必达。
2) **创建链路补齐 description（已完成）**
   - createPPT / updatePPT 已传入 description，并在 description 更新时强制重算 embedding。
3) **加入相似度阈值/质量兜底（已完成）**
   - hybridSearch 已按 `VECTOR_SIMILARITY_THRESHOLD` 过滤低相似度结果，不足再补 SQL。
   - 阈值仍可从日志分布继续迭代（如 0.25/0.3 起试）。

**P2（性能/体验优化）**
4) **向量检索支持过滤**
   - 方案 A：先向量召回 TopN，再在内存中过滤 category/language/status；
   - 方案 B：尝试在 SQL 里加过滤并配合 partial HNSW 索引（若数据库支持）。
5) **缓存 query embedding**
   - 对热词/高频 query 做 KV/Redis 缓存，减少远程 embeddings 调用。
6) **多语言/中文变体增强**
   - 对 query 做简繁/同义变体 embedding（平均或取最高 similarity），提升中文召回稳定性。

**P3（规模化/SEO扩展）**
7) **长尾 SEO 落地页**
   - 以 hot_keywords/pinned_keywords 为起点生成 SSR 搜索落地页（`/ppt/search/<kw>`），静态渲染 Top 20 结果并带 JSON‑LD/metadata。
   - 首页热词跳转到该落地页，提高可索引覆盖。
8) **向量存储拆表预案**
   - 数据量继续增长到 1e6 级或行宽压力增大时，可考虑 `ppt_embedding` 独立表/分区，或外置向量库（Qdrant/Weaviate）。
9) **脚本与 schema 对齐**
   - 更新/标注 `scripts/setup-pgvector.ts`、`scripts/db-migration/setup-search.sql`，避免生成旧版 search_log。

### 十、后续可跟踪指标
- embedding 覆盖率（embedding 非空且 `embedding_status='success'` / total_ppt）
- embedding 生成成功率 / 平均耗时 / 失败重试次数
- vector 命中率（vectorSearch 返回>0 的占比）
- similarity 分布（P50/P90）
- SQL 降级率（searchType='sql' 占比）
- 首页搜索 CTR / 下载转化
