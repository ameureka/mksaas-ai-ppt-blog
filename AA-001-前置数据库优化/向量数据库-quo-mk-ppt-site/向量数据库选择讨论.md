## 向量数据库方案澄清

### 我们讨论的推荐方案是：**pgvector (PostgreSQL 扩展)**

不是 Pinecone。

### 方案对比

| 方案 | 我们的选择 | 说明 |
|------|-----------|------|
| pgvector | ✅ 推荐 | PostgreSQL 原生扩展，Neon 已支持 |
| Pinecone | ❌ 未选择 | 独立向量数据库，需额外付费和维护 |
| Redis Stack | ❌ 未选择 | 不适合当前架构 |

### 为什么选 pgvector 而不是 Pinecone？

┌─────────────────────────────────────────────────────────────────────────────┐
│                    pgvector vs Pinecone                                      │
├─────────────────────────┬───────────────────────────────────────────────────┤
│      pgvector (推荐)     │              Pinecone                             │
├─────────────────────────┼───────────────────────────────────────────────────┤
│ ✅ 同一个数据库          │ ❌ 独立服务，需要同步数据                          │
│ ✅ 免费 (Neon 已支持)    │ ❌ 付费 ($70+/月起)                               │
│ ✅ 无需维护两套系统      │ ❌ 需要维护 ID 映射关系                            │
│ ✅ 事务一致性            │ ❌ 最终一致性                                      │
│ ✅ 简单，一个 SQL 搞定   │ ❌ 需要两次查询 (向量库 + 主库)                    │
│ ⚠️ 大规模性能一般        │ ✅ 大规模性能优秀                                  │
├─────────────────────────┴───────────────────────────────────────────────────┤

## pgvector 容量评估

### 性能参考

| 数据量 | pgvector 性能 | 是否够用 |
|--------|--------------|----------|
| 1,000 | < 10ms | ✅ 绰绰有余 |
| 10,000 | < 50ms | ✅ 完全够用 |
| 100,000 | < 200ms | ✅ 够用 |
| 1,000,000 | 需优化索引 | ⚠️ 考虑 Pinecone |
| 10,000,000+ | 性能瓶颈 | ❌ 需要专业向量库 |

### 10,000 条数据的存储估算

每条 PPT 向量大小:
- 1536 维 × 4 字节 (float32) = 6KB

10,000 条总计:
- 向量数据: 6KB × 10,000 = 60MB
- 加上索引: 约 100-150MB

结论: Neon 免费版 (512MB) 都能轻松承载
