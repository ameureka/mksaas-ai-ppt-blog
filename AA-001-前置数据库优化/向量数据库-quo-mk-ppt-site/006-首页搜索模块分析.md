## 三、数据链路详解

### 3.1 热门搜索标签数据流

```
┌─────────────────────────────────────────────────────────────┐
│  Step 1: 页面加载                                            │
│  useEffect → fetch('/api/hot-keywords')                      │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│  Step 2: API 路由                                            │
│  /api/hot-keywords/route.ts                                  │
│  → getHotKeywords()                                          │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│  Step 3: 数据获取逻辑                                         │
│  1. 查询 pinned_keywords (运营置顶)                           │
│  2. 查询 hot_keywords (自动计算)                              │
│  3. 合并去重，取前8个                                         │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│  Step 4: SQL 执行                                            │
│  SELECT keyword FROM pinned_keywords ORDER BY rank LIMIT 8   │
│  SELECT keyword FROM hot_keywords ORDER BY rank LIMIT 8      │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│  Step 5: 返回前端                                            │
│  { success: true, data: ['培训', '汇报', '总结', ...] }       │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 搜索执行数据流

```
┌─────────────────────────────────────────────────────────────┐
│  Step 1: 用户输入/点击热词                                    │
│  handleSearch(query) 或 handleKeywordClick(keyword)          │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│  Step 2: API 请求                                            │
│  fetch(`/api/ppts?search=${encodeURIComponent(query)}`)      │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│  Step 3: 路由判断                                            │
│  有 search 参数 && 无 category/status                        │
│  → 使用 hybridSearch()                                       │
│  否则 → 使用 getPPTs()                                       │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│  Step 4: 混合搜索策略                                         │
│  1. vectorSearch() - 向量搜索                                │
│     → 生成查询向量 (BAAI/bge-m3)                             │
│     → pgvector 余弦相似度搜索                                │
│     → 结果 >= 5 条? 返回                                     │
│                                                              │
│  2. sqlSearch() - SQL 降级搜索 (不足5条时)                    │
│     → ILIKE 模糊匹配 title/description/author/tags           │
│     → 按 download_count 排序                                 │
│                                                              │
│  3. 合并结果，返回 searchType                                │
│     → 'vector' | 'sql' | 'hybrid'                            │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│  Step 5: 返回结果                                            │
│  { success: true, data: { items, total }, searchType?, meta? }│
│  （search 分支返回 searchType/meta；SQL 分支无 searchType/meta）│
└─────────────────────────────────────────────────────────────┘
```

### 3.3 热门关键词更新流程 (Cron)

```
Trigger: Vercel Cron 定时任务 → GET /api/cron/update-hot-keywords
    ↓
Step 1: 统计最近7天搜索词频率
    SELECT keyword, COUNT(*) FROM search_log
    WHERE created_at >= 7天前
    GROUP BY keyword ORDER BY COUNT(*) DESC LIMIT 50
    ↓
Step 2: 统计下载量 Top PPT 的标签
    SELECT unnest(tags), SUM(download_count)
    FROM ppt WHERE deleted_at IS NULL
    GROUP BY unnest(tags) ORDER BY score DESC LIMIT 50
    ↓
Step 3: 合并计算最终得分
    finalScore = searchScore * 0.6 + downloadScore * 0.4
    ↓
Step 4: 写入 hot_keywords 表
    DELETE FROM hot_keywords;
    INSERT INTO hot_keywords (Top 8)
```

### 4.2 向量搜索 vs SQL 搜索对比

| 特性 | 向量搜索 (vectorSearch) | SQL 搜索 (sqlSearch) |
|------|------------------------|---------------------|
| 输入处理 | 生成 1024 维向量 | 直接使用关键词 |
| 匹配方式 | 余弦相似度 | ILIKE 模糊匹配 |
| 语义理解 | ✅ "新能源"匹配"清洁能源" | ❌ 只能精确匹配 |
| 依赖条件 | embedding 字段有值 | 无特殊依赖 |
| 性能 | 需向量索引优化 | 较快 |
| 可用性 | 可能失败 | 100% 可用 |

## 六、优缺点分析

### 6.1 优点
| 优点 | 说明 |
|------|------|
| ✅ 混合搜索策略 | 向量优先，SQL 降级，保证可用性 |
| ✅ 热词动态更新 | 基于搜索+下载数据自动计算 |
| ✅ 运营可控 | pinned_keywords 支持手动置顶 |
| ✅ 搜索日志能力完备 | 具备 search_log 表与写入接口，但首页搜索尚未集成日志记录 |
| ✅ 多语言向量 | BAAI/bge-m3 支持中英文 |

### 6.2 潜在问题
| 问题 | 严重程度 | 说明 |
|------|----------|------|
| ⚠️ 搜索日志未记录 | 中 | /api/ppts 未写入 search_log（未调用 logSearch/sync-history） |

## 八、补充核对（基于自查）
- API 返回结构：search 分支会返回 `searchType`，当前未返回 meta/durationMs；search 分支无分页 offset，固定一页 `pageSize`。
- 搜索日志：前端首页未写入 `search_log`（需显式调用 logSearch 或 sync-history）。
- 搜索建议：`/api/search/suggestions` 路由存在，首页未集成实时建议。
- 结果字段：响应不含 rating/reviewCount，前端卡片使用默认值；如需展示评分需扩展字段或二次查询。
- 性能：向量列未建 HNSW/IVFFlat 索引，向量查询为全表扫描；可添加 `CREATE INDEX ... USING hnsw`.

## 十、总结

### 当前状态
搜索模块采用**向量+SQL 混合搜索**策略，热门关键词支持**自动计算+运营置顶**双模式。

### 核心数据流
```
用户输入 → API 路由 → hybridSearch() → vectorSearch() / sqlSearch() → 返回结果
热词展示 → API 路由 → getHotKeywords() → pinned + auto 合并 → 返回 Top 8
```

### 关键问题
1. 🔴 **性能**: embedding 字段无向量索引
2. 🟡 **数据**: 搜索日志未记录
3. 🟡 **体验**: 无实时搜索建议

### 建议优先级
1. **立即修复**: 添加搜索日志记录
2. **本周完成**: 实现搜索建议功能
3. **后续优化**: 缓存层、质量监控
