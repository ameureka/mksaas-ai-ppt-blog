# PPTHub 搜索系统重构 - 5 小时无人值守最终方案

> **创建日期**: 2025-12-07
> **状态**: 已确定，待执行
> **预估时间**: 约 5 小时

---

## 一、方案概述

利用 Kiro CLI 的 Agent、TODO List、Checkpoint、Knowledge、Hooks 等能力，实现 PPTHub 搜索系统 7 个功能模块的无人值守自动化重构。

### 执行目标

| Spec | 功能 | 预估时间 |
|------|------|----------|
| 01-vector-search | pgvector 向量搜索 | 60 min |
| 02-hot-keywords | 动态热门关键词 | 40 min |
| 03-search-experience | 防抖、历史、自动补全 | 50 min |
| 04-empty-result | 空结果处理、推荐 | 40 min |
| 05-search-scope | 扩展搜索字段 | 20 min |
| 06-search-analytics | 搜索埋点日志 | 40 min |
| 07-multilingual | 繁简体中文支持 | 30 min |

**总计**: ~280 分钟 (约 4.5-5 小时)

---

## 二、核心决策

| # | 决策项 | 方案 |
|---|--------|------|
| 1 | 执行方式 | 混合模式：7 个顶层 TODO + Phase 子任务 |
| 2 | 验证频率 | 分层：Hook(lint) / Phase(lint+build) / Spec(功能测试) |
| 3 | 检查点 | 每 Phase 创建，约 41 个检查点 |
| 4 | Embedding API | SiliconFlow (`BAAI/bge-large-zh-v1.5`)，fallback `OPENROUTER_API_KEY` |
| 5 | 上下文管理 | Specs → Resources (始终可见)，代码 → Knowledge (按需搜索) |

## 四、启动流程

### 步骤 1：启用实验功能

```bash
kiro-cli settings chat.enableThinking true
kiro-cli settings chat.enableTodoList true
kiro-cli settings chat.enableCheckpoint true
kiro-cli settings chat.enableKnowledge true
```

### 步骤 2：创建 Agent 配置

```bash
mkdir -p .kiro/agents
# 将上述 JSON 保存到 .kiro/agents/ppt-search-refactor.json
```

### 步骤 3：启动 Agent

```bash
cd /Users/ameureka/Desktop/mksaas-ai-ppt-blog
kiro-cli chat --agent ppt-search-refactor
```

### 步骤 4：初始化（在 chat 中执行）

```bash
# 信任所有工具（无人值守必须）
/tools trust-all

# 初始化检查点
/checkpoint init

# 添加代码到 Knowledge
/knowledge add src/db/schema.ts
/knowledge add src/app/api/ppts/
/knowledge add src/app/[locale]/(marketing)/ppt/page.tsx
```

### 步骤 5：开始执行

Agent 会自动开始执行，按 prompt 中的指令：
1. 创建 TODO List
2. 按顺序执行 7 个 Specs
3. 每个 Phase 后验证
4. 遇到问题尝试修复或记录后继续

## 七、中断恢复

### 场景 1：意外中断

```bash
# 恢复对话
kiro-cli chat --resume

# 恢复 TODO List
/todos resume

# 查看检查点
/checkpoint list
```

### 场景 2：需要回滚

```bash
# 查看检查点
/checkpoint list

# 回滚到指定检查点（保留新文件）
/checkpoint restore <tag>

# 完全回滚（删除新文件）
/checkpoint restore <tag> --hard
```

### 场景 3：查看进度

```bash
# 查看 TODO 进度
/todos view
```

## 十一、风险与应对

| 风险 | 应对措施 |
|------|----------|
| API Key 失效 | agentSpawn 检查，失败时提示 |
| 数据库迁移失败 | 检查点回滚，手动修复后继续 |
| 代码冲突 | Knowledge 搜索现有实现，避免覆盖 |
| 上下文溢出 | Specs 用 Resources，代码用 Knowledge |
| 长时间无响应 | 检查网络，必要时 `/todos resume` |
