## 3. 搜索机制原理

### 三层搜索架构

#### 第一层：向量搜索（Vector Search）
```sql
-- 使用 pgvector 的 <=> 运算符计算余弦距离
SELECT *, 1 - (embedding <=> query_vector) as similarity
ORDER BY embedding <=> query_vector
```
- **原理**: 余弦相似度，语义匹配
- **优势**: 理解语义，处理同义词
- **场景**: 模糊搜索，概念搜索

#### 第二层：SQL搜索（SQL Fallback）
```sql
-- ILIKE 模糊匹配多个字段
WHERE title ILIKE '%keyword%' 
   OR description ILIKE '%keyword%'
   OR array_to_string(tags, ',') ILIKE '%keyword%'
```
- **原理**: 字符串模式匹配
- **优势**: 精确匹配，无需向量
- **场景**: 向量失败时的降级

#### 第三层：混合搜索（Hybrid Search）
- **策略**: 向量优先，SQL补充
- **判断逻辑**:
  - 向量结果≥5条 → 仅返回向量结果
  - 向量结果1-4条 → SQL补充至20条
  - 向量结果0条 → 完全降级到SQL

### 搜索增强机制

#### 中文变体处理（OpenCC）
```typescript
getChineseVariants("数据") → ["数据", "數據", "数据"]
```
- 繁简体自动转换
- 扩展搜索覆盖面

#### 拼写纠错（Levenshtein距离）
```typescript
findSimilarWords("pythno", hotKeywords, 2) 
→ [{word: "python", distance: 1}]
```
- 编辑距离≤2的相似词
- 基于热词库纠错

#### 搜索建议（多源融合）
1. **用户历史** (优先级100): 个人搜索记录
2. **热门关键词** (优先级50): 全站热词
3. **标题匹配** (优先级10): PPT标题

## 5. 关键问题与优化建议

### 已发现问题
1. **模型不一致**: 
   - generatePPTEmbeddingAsync使用'bge-large-zh-v1.5'
   - 批量脚本使用'bge-m3'
   - 建议：统一为'bge-m3'

### 优化建议
1. **向量索引**: 确认pgvector索引是否已创建
   ```sql
   CREATE INDEX ON ppt USING ivfflat (embedding vector_cosine_ops);
   ```

2. **数据完整性**: 检查NULL向量
   ```sql
   SELECT COUNT(*) FROM ppt WHERE embedding IS NULL;
   ```

3. **搜索性能**: 监控search_log分析瓶颈

## 总结

系统采用了**向量搜索为主、SQL搜索为辅**的混合策略，通过pgvector实现语义搜索，配合中文繁简转换、拼写纠错、多源建议等增强机制，构建了完整的智能搜索体系。数据库设计遵循了优化原则，包括软删除、复合索引、外键约束等最佳实践。
