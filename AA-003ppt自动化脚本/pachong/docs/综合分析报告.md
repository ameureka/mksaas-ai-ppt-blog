## 2. 技术可行性与覆盖率

### 代码覆盖 (Code Coverage)
经过验证，现有爬虫架构完美支持以上四大频道：
1.  **列表解析 (`Paginator`)**: 所有频道均采用标准的 `ul.tplist > li` 网格布局，解析逻辑通用。
2.  **详情提取 (`Fetcher`)**: 详情页结构统一，均包含标题、下载列表、Tag 标签及 `.ppt_info` 元数据区。
3.  **下载机制 (`Downloader`)**:
    - **文件**: 支持防盗链 (`Referer`) 下载。
    - **封面**: 自动探测并下载封面图片，需带 Referer。
    - **网盘**: 自动解析夸克网盘链接作为备用。

### 去重机制 (Deduplication Strategy)
系统设计天然防止重复下载和记录：
1.  **数据库级去重**: `tasks` 表以 **URL** 为唯一索引 (`UNIQUE`)。
    - 当爬虫在不同频道遇到同一个 URL 时（例如“医疗模板”既在模板区也在行业区），数据库执行 `UPSERT` 操作：**保留原有记录，仅更新时间戳**。
2.  **物理去重**:
    - 任务状态一旦标记为 `COMPLETED`，后续扫描到的相同 URL 即使被触发，也会因状态检查而被跳过下载。
    - **文件名唯一性**: 文件名格式为 `{aid}-{title}.zip`。即使在极端情况下重复下载，同名文件会覆盖，不会产生垃圾冗余。

## 3. 分类与标签体系设计

为了方便后续的资源整理和检索，我们确立了**三层标签体系**。所有元数据均存储在 SQLite 数据库的 `meta` 字段中。

### L1: 来源频道 (Source Channel)
- **定义**: 资源被发现时的顶级入口。
- **字段**: `channelId` (如 `ppt_xiazai`)。
- **作用**: 物理目录隔离，便于通过文件夹管理。

### L2: 核心分类 (Primary Category)
- **定义**: 资源在站点上的具体归属栏目。
- **字段**: `channelName` (如 "商务PPT", "医疗PPT", "元旦PPT")。
- **来源**: 详情页抓取的面包屑导航或分类链接文本。
- **作用**: 最核心的业务分类维度，用于建立文件夹层级或导航菜单。

### L3: 语义标签 (Semantic Tags)
- **定义**: 描述资源特征的关键词。
- **字段**: `tags` (JSON 数组, 如 `["蓝色", "微立体", "医生"]`)。
- **来源**: 详情页底部的 Tag 云。
- **作用**: 用于全文检索、相关推荐和多维筛选。
