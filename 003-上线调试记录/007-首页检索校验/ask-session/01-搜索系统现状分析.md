## 二、详细分析

### 2.1 当前搜索实现

**实现方式**: SQL `ILIKE` 模糊匹配

**代码位置**: `src/actions/ppt/ppt.ts`

```typescript
if (params?.search?.trim()) {
  const keyword = `%${params.search.trim()}%`;
  conditions.push(
    or(
      ilike(pptTable.title, keyword),      // 标题匹配
      ilike(pptTable.author, keyword),     // 作者匹配
      sql`array_to_string(tags, ',') ILIKE ${keyword}` // 标签匹配
    )
  );
}
```

**数据流**:
```
前端输入 → /api/ppts?search=xxx → getPPTs() → buildWhere() → PostgreSQL ILIKE
```

### 2.4 向量与原数据关系

**关系类型**: 1:1 对应

```
┌─────────────────────────────────────────────────────────────────┐
│  ppt 表一条记录                                                  │
├─────────────────────────────────────────────────────────────────┤
│  id: "ppt_001"                                                  │
│  title: "年终总结模板"                                           │
│  description: "适用于企业年度工作汇报..."                         │
│  tags: ["商务", "总结", "汇报"]                                  │
│                    │                                            │
│                    ▼ 文本拼接后生成向量                           │
│  embedding: [0.012, -0.034, 0.056, ... 共1536维]                │
└─────────────────────────────────────────────────────────────────┘
```

**向量生成公式**:
```
input_text = title + " " + description + " " + tags.join(" ")
embedding = OpenAI.embed(input_text, model="text-embedding-3-small")
```

### 2.5 推荐向量方案

**选择**: pgvector (PostgreSQL 扩展)

**方案对比**:

| 因素 | pgvector ✅ | Pinecone ❌ | Redis Stack ❌ |
|------|-------------|-------------|----------------|
| 成本 | 免费 (Neon 支持) | $70+/月 | 需付费 Redis |
| 复杂度 | 低 (同库同表) | 高 (独立服务) | 中 |
| 数据同步 | 无需 | 需要维护 | 需要维护 |
| 10,000条性能 | ✅ <50ms | ✅ <10ms | ✅ <20ms |
| 事务一致性 | ✅ 原生支持 | ❌ 最终一致 | ❌ 最终一致 |

**选择理由**:
1. Neon PostgreSQL 原生支持 pgvector
2. 10,000 条数据量 pgvector 完全够用
3. 同库同表，无需维护数据同步
4. 免费，无额外成本
